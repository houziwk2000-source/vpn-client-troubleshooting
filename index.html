第一次使用：从安装到完成验证

1. 先确认软件与订阅能够配合

从客户端项目自己的发布页或设备认可的应用商店确认下载来源、系统版本和 CPU 架构。不要仅因搜索结果写着“官网”就安装，不通过关闭安全防护来解决安装问题。遇到系统拦截时先核实来源和兼容要求，仍无法确认就停止安装。

客户端与网络服务是两件事：安装软件不会自动获得节点；购买服务也不一定包含客户端费用。先确认服务提供的订阅格式受你的软件支持，再选择对应入口，不把网页首页、订单页面或单个节点文本当成完整订阅。

2. 导入自己的完整订阅，并选中配置

在所用客户端的官方教程中找到“订阅／配置／Profiles”等对应功能，添加自己账户提供的完整地址。菜单名称随软件和版本变化，不能照着另一款软件找完全相同的按钮。

导入后检查三件事：配置是否保存、最近更新是否成功、当前启用的是否为这份配置。成功标准是这三项成立并看到相应节点或策略，而不只是出现一条导入提示。 更新前保留原可用配置，不先删除唯一副本。

订阅地址通常带有私人凭据。不要粘贴到公开 Issue、聊天群、陌生在线转换或测速网站；反馈截图也要遮盖完整地址和二维码。

3. 验证“目标应用实际经过了什么路径”

在当前策略中选择一个节点或服务建议的策略，再按软件教程启用需要的代理接管方式。系统代理只影响遵循该设置的应用；不要因为开关亮了，就认定所有程序都已接入。

先打开一个你需要且有权访问的普通小页面，再到客户端的连接记录中核对对应目标、策略和状态。然后完成一次真实的小任务，例如加载课程目录或发送一条不含私人资料的短问题。页面能打开，不等于上传、播放、登录等后续功能都正常。

仍失败时： 保留时间与具体提示，进入下面对应章节。先验证一条路径，不密集测速全部节点，也不以一次低延迟数字替代真实任务。

订阅导入失败或没有节点

按下面顺序排查，每一步只改一个条件：

  1. 确认地址用途。 回到自己账户内的订阅区域，核对是否选了适用于该客户端的格式。不要把品牌主页、教程地址、过期分享链接当成订阅。
  2. 确认账户和地址状态。 检查服务是否到期、订阅是否被重置或撤销。更新订阅地址后，需要在设备上同步替换；续费不一定会自动修复旧地址。
  3. 读错误，不只看“失败”。 401/403 常与认证或访问策略有关，404 常表示该地址没有对应资源，超时可能发生在网络或服务端；这些只是排查线索，不足以单独确定原因。保留脱敏后的状态码与时间。
  4. 区分下载与解析。 配置已下载但提示格式或字段错误时，核对客户端、内核版本和订阅格式；收到登录页面、验证页面或错误文本，不等于得到了可解析配置。不要公开粘贴完整响应，它可能包含私人节点。
  5. 检查当前启用项。 更新成功后仍无节点时，确认不是选中了空白配置、旧配置或不适用的筛选条件。若软件使用策略组，按其教程查看组内节点，不把组名当成单个节点。

成功标准： 当前配置能够更新，节点或策略可见，随后能建立一次实际连接。仍不成功时，把客户端版本、格式类型、错误阶段和脱敏提示交给实际服务支持，不要反复删除重装或更换未知转换工具。

已连接但网页或应用打不开

1. 先区分“进程启动”与“请求成功”

某些界面的“已连接”只说明客户端或系统 VPN 会话处于启用状态。打开目标页面后，看连接记录里有没有该请求：完全看不到时，先核对应用代理设置和接管范围；能看到但连接报错时，再检查节点、目标和错误详情。

2. 用同一目标比较规则与全局，测试完恢复

适用 Mihomo 的配置中，rule 按规则匹配，global 使用 GLOBAL 策略组里选定的出站，direct 为直连。切到全局之前仍要检查 GLOBAL 组选择了什么；它不是“自动选最快节点”，也不能替代应用流量是否已被接管的检查。说明依据：Mihomo 运行模式文档。

如需排查规则：先记录原模式和策略，在你有权访问的同一目标上做一次短时对比，然后恢复原模式。全局会改变已接管请求的路由选择，并可能增加代理用量；不要把它当成永久通用修复。全局可用、规则不可用时，继续核对命中的规则和出站，而不是直接断言服务故障。

3. 不把 TUN 与 DNS 当成万能开关

TUN 通过虚拟接口配合路由等设置处理流量，涉及系统权限、出口接口和 DNS；并不代表无条件接管所有程序。若只有不遵循系统代理的应用失败，先确认软件推荐的接入方式，再按对应版本教程考虑是否需要 TUN。

已经启用 TUN 时，检查是否还有另一个代理或 VPN 同时管理路由；只在自己有权限且知道如何恢复时，逐项暂停其中一个进行对比。不要同时叠加多个工具，也不要随意改 MTU、路由表或导入网上不明配置。具体行为见 Mihomo TUN 文档。

只有日志出现解析错误、找不到主机等线索时，再核对 DNS 所在层：浏览器、系统和客户端都可能有相关设置。先记录原值和客户端配置，再按官方文档调整一处；无改善就恢复。不要一开始就替换所有 DNS 或关闭证书校验。参考：Mihomo DNS 配置。

4. 目标平台的提示要单独处理

限流、额度不足、账户权限、内容地区限制和文件格式错误，各有自己的处理条件。如果普通页面可用而某项功能失败，先按平台提示检查；频繁重试同一上传或付费请求，可能产生重复任务或额外消耗。网络套餐不自动包含 AI 会员、API 额度或影音会员。

成功标准： 原先失败的同一个应用和同一个小任务可以完成，且记录了实际有效的改动。只恢复另一个网页，不算解决原问题。

退出客户端后网络没有恢复

适用于原本可以正常联网、关闭客户端后才出现故障的设备。先保存工作，避免直接执行系统网络重置或删除网卡：

  1. 如果软件仍可打开，先在软件内关闭本次启用的系统代理或 TUN，再按正常流程退出。不要只结束进程，让系统继续指向已停止的本地服务。
  2. 检查系统代理是否仍指向该软件使用的本地地址与端口。仅在确认该设置由本次操作创建、不是组织或其他服务要求时恢复操作前的值；不要把所有代理设置一律清空。
  3. 检查系统 VPN/网络连接界面，确认本次会话已断开。使用受管理设备或其他 VPN 时，不删除不认识的配置。
  4. 若先前手动更改过 DNS、路由或应用独立代理，按记录逐项恢复。没有记录、无法判断归属时，先找管理员或该客户端支持，不猜参数。
  5. 用不需要代理的普通页面验证基础网络，再重新打开客户端验证目标任务。基础网络仍失败时，换一个已知正常网络进行对照，并保留错误，不立即重装系统或关闭防火墙。

以后每次调整设置前，记录原模式、接管方式与修改项；记录留在自己设备中，不公开含凭据的配置备份。

流量、到期和重置怎么区分

  • 到期时间影响服务期限；流量余额影响可用传输额度；重置时间说明额度何时按套餐规则刷新。续费、重置包和叠加包是否改变这些字段，要看实际条款，不能互相替代。
  • 家庭共享可能共同消耗账户总量。系统更新、照片同步、离线课程和 AI 文件上传，也可能经过该连接，不只视频播放才产生流量。
  • 设备统计与服务账户统计可能使用不同单位、时间窗口和计算范围。先对齐周期，再观察差异；单凭两个数字不相等，不能判断异常扣费。
  • 购买前确认付款周期。年付金额除以12得到的是月均成本，不代表可以按该价格月付；“不限设备”也不等于不限流量或不限并发。
